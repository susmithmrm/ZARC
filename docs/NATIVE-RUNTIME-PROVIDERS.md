# Integrated simulator Zbus and device runtime PM

All four native simulator profiles now include the real Zephyr Zbus front end and device-runtime PM APIs. The controller-owner drains its bounded observation history through the existing native channel/listener and checks the copied event against its source before advancing a separate subscriber cache. A gap, overflow, mismatch or invalid epoch invalidates the observer; the application refuses to continue rather than silently presenting stale values. An explicit snapshot barrier reinitializes the subscriber during lifecycle recovery. This is a same-owner synchronous reference path, not a timing-qualified independent subscriber.

The separate device worker owns a native runtime-PM reference on a simulator-only spy device. Its serialized commands suspend and resume that reference; sample/effect requests are unavailable when unpowered. Stop releases a held reference. The smoke tests check observed device feedback through the subscriber cache, then quiesce, balance PM references, resume with a fresh barrier and stop. The manifests identify Zbus and runtime PM as selected features. Physical device PM, wake latency, approved observer allocation, watchdog and durable storage integration remain outstanding; no real rail or vehicle function is operated.
