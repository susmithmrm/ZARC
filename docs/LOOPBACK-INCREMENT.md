# Independent process fixture

The controller and broker are distinct native desktop executables, connected using ephemeral loopback TCP. The controller owns its tick progression and a benign virtual device, continues independently after broker exit, and publishes a fresh observation after reconnect. The broker opens a new session rather than replaying a stale command. CTest launches both processes using Python when an interpreter is available.

This is a bounded lab fixture, not a production broker or transport provider. It uses a fixed fixture principal and assumes zero transit age on loopback; no real peer authentication, security protocol, delegated client authorization, production queue priority or network timing evidence. The controller uses a single client socket, polling and bounded sends; a peer must not use the fixture as a production interface. The virtual feedback is generated by a separate fixture state, not hardware. Broker restart and disconnect completion are exercised; controller restart, adversarial scheduling, comprehensive fault injection and selected-stack conformance remain open.

Trace candidates: CON-002/007/009/010/012/015/018 and HOST broker independence. No requirement is closed.
