# Runtime resource counters and scoped health

The sole runtime owner now exposes bounded read-only resource counters (completed, missed and skipped periodic releases; observed maximum release-to-completion; retained request, outstanding effect and diagnostic high-water counts). Counters persist across logical suspend/resume within a runtime instance and reset at new initialization. The periodic completion counter is scheduler accounting, not a count of valid physical observations; health remains separate. No physical RAM/flash/stack or WCET claim is made.

The reference wire dispatcher implements GetHealth (operation 8), with an exact 4-byte little-endian endpoint ID and independent scope check. Completed response length 28: status u8, schema version u8=1, endpoint u32, failure flags u32 (alive=1, deadline=2, logical=4), ready u8, ownership flags u8 (pending=1, outstanding effect=2), last accepted sample tick u64 and source sequence u64. Boot/session and request correlation remain in the frame header. A health response is not physical completion. Unallocated or unauthorized endpoints cannot reveal their state; no remote maintenance action is exposed. The desktop loopback legacy endpoint does not yet implement this operation. Tests exercise bounded counters, missed releases and endpoint scope. This is a candidate semantic extension, not an approved OEM interface.
